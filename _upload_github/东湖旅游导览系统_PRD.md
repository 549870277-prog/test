# 东湖旅游导览系统 PRD（简版）

版本：V1.0 ｜ 日期：2026-10-12 ｜ 形态：手机网页

## 1. 产品概述

面向到东湖游玩的游客，提供景点介绍、路口指引、点赞评论和推荐路线可视化，帮助游客了解景点、选择游览顺序。

**待验证的问题：**游客初次游玩时不熟悉景点分布和路口方向，难以安排顺路的行程。[假设，尚未开展用户调研]

用户选择入口，选择游玩时间，全天，上午，下午，选择游玩的强度，轻度散步，中度徒步，重度骑行，即可有推荐路线。
按照穷举法，分别列出最优的旅游路线。

**范围约定：**本稿按武汉东湖设计，首版只覆盖一个选定片区，配置 3～5 个景点和 3 个关键路口。[方案假设] 景点名称、介绍、图片、坐标和道路连接关系在上线前核实；示例路口不代表真实路口。


## 2. 用户与使用场景

目标用户为希望简单了解景点、按路线游玩的普通游客。

| 用户需求 | 验收标准 |
| --- | --- |
| 我想知道景点有什么可看 | 点击景点可查看图片、简介和建议游览时长 |
| 我想知道到路口后往哪走 | 点击路线中的路口，可看到下一站及方向提示 |
| 我想表达喜欢、分享体验 | 可以点赞、取消点赞、发布评论并看到结果 |
| 我想少走一些路 | 选择起点和景点后，可以查看推荐顺序及优化前后的距离 |

## 3. 功能需求

首版只做以下功能，均为必需功能。

### 3.1 景点介绍

- 首页展示景点列表，每项包含名称、封面图和一句话简介。
- 详情展示名称、图片、简介、建议游览时长、地图位置、点赞数和评论。
- 提供“加入路线”按钮，再次点击可移除；同一景点不能重复加入。
- 内容预先配置，不建设复杂内容管理后台。

### 3.2 地图与路口指引

- 地图展示景点和 3 个关键路口，使用不同图标区分。
- 点击景点标记进入详情；点击路口展示名称和通往哪些景点。
- 已生成路线时，路口提示下一站、行进方向和剩余距离。
- 原型可使用“路口 A、B、C”占位；实际指引必须基于核实后的道路和位置。

### 3.3 点赞

- 点赞对象为景点，点击后数量加 1，再次点击取消并减 1。
- 首版使用匿名访客标识，同一浏览器对同一景点只能保持一个赞。
- 刷新后保留状态；不保证跨设备或清除浏览器数据后的身份一致性。
- 保存失败时恢复原状态，并提示重试。

### 3.4 评论

- 游客可在景点详情发布纯文字评论，昵称可选，默认“游客”。
- 评论长度为 1～200 字，去除首尾空格后不能为空。
- 按发布时间倒序展示昵称、内容和时间；暂无评论时显示空状态。
- 发布成功后立即显示；失败时保留输入内容，允许重试。
- 游客可删除本人当前访客标识下的评论；维护人员可移除不当内容。
- 不做回复、图片评论和评论点赞。

### 3.5 推荐路线与可视化

- 游客从预设入口或景点中选择起点，再选择 1～5 个想去的景点。
- 默认以最后加入的景点为终点，中间景点按加入顺序构成原路线。
- 点击“优化路线”，在保持起终点不变、所有所选景点均经过的条件下，调整中间景点顺序，优先减少总步行距离。
- 距离以已核实的可步行道路计算，不用直线距离代替道路距离。
- 地图用彩色折线和方向箭头展示推荐路线，用数字标记景点顺序，并标出途经路口。
- 地图下方同步展示游览顺序、总距离、预计步行时间及相比原路线减少的距离；步行时间按统一速度估算，不含景点停留时间。
- 支持切换“原路线 / 推荐路线”进行对比；推荐距离不得大于原路线。
- 没有更短方案时提示“当前顺序已较顺路”；无法连通时指出不可达景点，提示修改选择，不绘制虚假连接线。
- 首版不考虑实时拥堵、天气、实时封路或语音导航；道路变化由维护人员更新。

## 4. 页面与流程

仅设置三个主要页面：

1. **首页 / 地图页：**景点列表、地图标记、路线入口。
2. **景点详情页：**图文介绍、点赞、评论、加入路线。
3. **路线页：**起点选择、已选景点、优化按钮、路线地图及距离对比。

主要流程：打开首页 → 查看景点 → 加入路线 → 选择起点 → 优化路线 → 查看地图和路口提示。

路线展示示例，仅表示界面结构，不代表真实东湖道路：

```text
起点 → 路口 A → 景点 1 → 路口 B → 景点 2 → 路口 C → 终点景点
```

## 5. 基本规则与技术边界

- 适配手机浏览器，页面宽度 375px 时无横向溢出。
- 正常网络和测试数据下，景点页及路线结果均在 3 秒内可用。[验收目标]
- 地图加载失败时保留景点列表与路线文字顺序，并提供重试入口。
- 地图之外必须有文字路线，不能只靠颜色表达游览顺序。
- 点赞和评论保存到服务端；评论按纯文本显示，单个访客每 10 秒最多发布一条。
- 首版手动选择起点，不依赖定位授权；不做注册登录、购票、支付、酒店推荐或社交关注。
- 基础数据包括景点、路口、可步行道路及其距离、访客点赞和评论。路线优化仅针对已录入片区。

## 6. 验收与效果评估

交付时检查：景点信息可查看、3 个路口可点击、点赞可撤销且刷新保留、评论可发布与删除、路线覆盖所有选定景点且道路连通、优化前后可对比。

主要效果指标为“游客能否独立完成路线规划”。当前没有基线；首轮邀请 5 位测试者，目标至少 4 位在 2 分钟内完成选景点、生成路线并说出下一站。[初始目标，非已有数据] 由项目负责人在首版验收时记录结果并决定是否简化流程。

## 7. 实施与待确认项

实施顺序：整理景点和道路数据 → 完成三个页面及点赞评论 → 接入路线计算和可视化 → 按上述场景验收。

开发前由项目负责人确认：

- 是否为武汉东湖，以及首版覆盖哪个片区。
- 实际景点、3 个路口和可步行道路资料；缺少真实数据时只能作为演示原型。
- 上线后的景点资料、道路变化及评论由谁维护。

后续仅在实际使用有需要时，再增加实时定位和更多片区。
